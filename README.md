# ftl-is-king/homowork C语言作业自动审批与评测系统

[![Evaluate Homework](https://github.com/ftl-is-king/homowork/actions/workflows/eval_url.yml/badge.svg)](https://github.com/ftl-is-king/homowork/actions/workflows/eval_url.yml)

自动化 C 语言作业审批平台。学生只需提交一个包含作业代码仓库 URL 的 GitHub Issue，系统在后台全自动拉取代码、编译测试、综合打分，并在该 Issue 下自动回复测试报告，成绩自动同步归档到 `test.csv`。

---

## 🌟 核心特性

- **极简提交（零配置）**：学生无需在个人仓库配置任何 Token 或 Secret，仅凭 Issue 提交公开仓库 URL 即可。
- **全自动性能打分**：
  - **正确率得分**（满分 60 分）：根据测试用例通过比例严格评定。
  - **运行时间得分**（满分 20 分）：基于执行耗时指数衰减打分，超时自动熔断（5 秒）。
  - **运行内存得分**（满分 20 分）：基于物理内存（RSS）占用指数衰减打分。
  - **最高分保留**：支持学生多次重测迭代，系统自动保留单题历史最高分。
- **学籍白名单核验**：内置 `DB.csv` 校验，机器人自动从代码注释提取学号姓名并与数据库核对。
- **成绩自动归档**：评测通过后成绩自动同步至主仓库 `test.csv`。

## 📝 Issue 规范写法（只有两栏，直接按如下格式填写）

进入 **[ftl-is-king/homowork Issues](https://github.com/ftl-is-king/homowork/issues)**，点击 **New Issue**：

GitHub Issue 界面非常简洁，**只有两栏（标题 Title 和正文 Leave a comment）**，请按如下规范填写：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 标题 (Title)：                                                              │
│ [作业提交] 202401010001 - 张三                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│ 正文 (Leave a comment)：                                                    │
│ https://github.com/zhangsan/c-homework                                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1. 标题栏 (Title) 填写规范
- **格式**：`[作业提交] 学号 - 姓名`
- **示例**：`[作业提交] 202401010001 - 张三`
- *注意：标题中只要包含“作业”二字，系统均会自动识别触发。*

### 2. 正文栏 (Leave a comment) 填写规范
- **填写内容**：直接粘贴你存放作业代码的**公开（Public）GitHub 仓库网址**。
- **示例**：`https://github.com/zhangsan/c-homework`
- *说明：**不需要在正文额外写学号姓名**！机器人克隆你的代码后，会自动从你代码的前三行注释中提取学号、姓名和邮箱，并与班级白名单比对。因此正文只要有仓库链接即可。*

## 💻 学生端代码文件组织与注释规范

机器人克隆你的仓库后，会根据以下规范寻找代码与识别身份：

### 1. 代码文件命名规范
必须以 **题目序号** 开头：
- 第 1 题：`1_main.c` 或 `1_xxx.c`（或单题作业命名为 `main.c`）
- 第 2 题：`2_main.c` 或 `2_xxx.c`
- 第 3 题：`3_main.c` 或 `3_xxx.c`
- 后续题目以此类推...

### 2. 代码头部注释规范（必须严格写在文件前 3 行）
每个 `.c` 文件的**前三行**必须是学号、邮箱和姓名（每行以 `//` 开头），这是机器人核验学籍的依据：
```c
// 202401010001
// zhangsan@example.com
// 张三

#include <stdio.h>

int main() {
    int n;
    if (scanf("%d", &n) == 1) {
        printf("%d,%d\n", n + 10, n + 10);
    }
    return 0;
}
```

## 🤖 评测反馈与多次迭代

1. **自动生成成绩单**：
   提交 Issue 后通常在 **1~2 分钟内**，机器人会在你的 Issue 下自动回复成绩单：
   | 题号 | 文件名 | 测试点 | 运行时间 (ms) | 运行内存 (KB) | 最终得分 | 状态 |
   |:---:|:---|:---:|:---:|:---:|:---:|:---:|
   | 第 1 题 | `1_main.c` | 5/5 | 11.2 | 1024 | **99.38** | ✅ 通过 |
2. **修改代码重测**：
   - 若测试点未全过，直接在你的个人仓库修改代码并 push。
   - 修改后，只需**重新编辑该 Issue 或发表新评论**，机器人将拉取最新代码重测。
   - 最终成绩以历史最高分为准。

## 🔒 隐私与敏感信息保护机制（公私仓库分离）

为了严格保护全班学生的个人隐私与成绩安全，系统采用**公私双仓库分离架构**：
1. **公开评测仓库 (`homowork`)**：
   - 本仓库保持公开，供学生提交 Issue 触发评测。
   - 仓库内**不存放任何真实学生名单和全班成绩**。
2. **私有成绩仓库 (`homowork-scores`)**：
   - 独立私有仓库（仅教师可见）：[https://github.com/ftl-is-king/homowork-scores](https://github.com/ftl-is-king/homowork-scores)
   - 专门存放真实学生白名单 `DB.csv` 与全班汇总成绩单 `test.csv`。
   - 评测机器人每次运行后，自动将成绩推送到私有仓库中存档。
   - **学生端隐私保护**：学生仅在自己的 Issue 评论区看到本人代码的测试反馈，外部任何访客均无法查阅全班成绩。

## 🚀 教师与维护者指南

### 1. 管理真实学生名单 (`DB.csv`)
请在私有仓库 **[homowork-scores](https://github.com/ftl-is-king/homowork-scores)** 中的 `DB.csv` 登记学生信息：
```csv
id,name,email
202401010001,测试学生,test@example.com
202401010002,张三,zhangsan@example.com
```

### 2. 配置作业题目与用例 (`config.py`)
在 `config.py` 中自由定义各题的测试输入与标准答案：
- `USER_INPUT`: 每道题的输入用例列表。
- `ANSWER`: 每道题的预期输出列表。
- `DEADLINE`: 截止提交时间。

### 3. 查看全班汇总成绩
教师只需进入私有仓库 **[homowork-scores](https://github.com/ftl-is-king/homowork-scores)**，即可随时查看或下载全班最新的 `test.csv` 成绩表。
